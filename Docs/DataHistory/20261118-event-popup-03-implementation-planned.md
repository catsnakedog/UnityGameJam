# 틱 기반 사건 팝업 구현 계획

- 사용자 요청: 틱 단위 이벤트 표시. 기존 data.events 예약을 이어 구현한다.
- 주기 정본 data.bunker.rules의 현재 randomEventEveryTicks=10을 유지한다. 새 타이머/주기 CSV 없음.
- Events.csv에 임시 사건 1~3(외부 신호, 전력 점검, 오래된 기록)을 추가한다. 필드는 기존 명세의 id/title/content만 사용. 균등 추첨하며 바로 직전 사건은 후보에서 제외(한 건이면 재사용).
- 기존 GameData/공용 DB를 사용. 초기 로드 및 팝업 중 벙커 틱을 소유자별로 정지하며 외부 Paused 값을 덮어쓰지 않는다. 마지막 틱은 사건을 열지 않는다.
- 명세/목록/소비 코드 재확인: 동일 사건 데이터 없음, 기존 예약 재사용. CSV는 UTF-8 BOM 포함.
- 구현·검증 전 계획 기록. 이전 이력은 보존한다.
