# 최종 점수와 엔딩 경계 검증

2026-11-23 KST, UnityGameJam. [변경 전 재현 및 계획](20261123-ending-score-plan.md).

[벙커 규칙](../DataSpecs/BunkerRules.md)의 `data.bunker.rules` 정본 `Assets/Settings/Shelter/BunkerRules.asset`에서 최종 평가 기준을 24틱에서 192틱으로 변경했다. Unity에서 변경 전 960틱·세 분야 100%를 입력해 0.078125점을 재현했다. 같은 진척으로 수정 후에는 0.625점이다. 신규 설치 도구의 960틱 초기 설정에도 같은 기준을 적용했다. 중간 발표는 기존에 쓰던 전체 회차 길이로 계산한다.

Assets·ProjectSettings·Docs의 계산기 호출부, 에셋, 설치 도구, 등록 목록을 대조했다. 평가 파라미터는 기존 BunkerRules가 공급하며 등급 경계는 기존 [엔딩 명세와 편집 시트](../DataSpecs/GameDevEndings.md)의 `data.game-dev.endings`에서 읽는다. 엔딩 CSV나 점수용 저장소를 추가할 필요가 없었다. 기존 주소로 [Addressables 콘텐츠 빌드](20261123-142847-6081375-data-built.md)를 완료했다.

| 최종 진척 합 | 세 자리 표시 | 실제 엔딩 |
|---:|---:|---|
| 0 | 0.000 | 남겨진 가능성 |
| 143 | 0.298 | 남겨진 가능성 |
| 144 | 0.300 | 첫 출시 |
| 239 | 0.498 | 첫 출시 |
| 약 239.99 | 0.500 미만 | 첫 출시 |
| 240 | 0.500 | 새로운 시작 |
| 300 | 0.625 | 새로운 시작 |

실제 규칙과 생성된 엔딩 카탈로그로 경계값을 검사했다. 플레이 모드에서는 중간 팝업과 습격을 끄고 벙커 시계로 959틱까지 진행했다. 기획 작업자를 배치한 회차는 마지막 틱에서 기획 99.99가 100에 도달해 합계 240을 한 번 제출했고, 컷씬 후 정산지에 ‘새로운 시작 / 평가 점수 0.500’이 표시됐다. 마지막에 작업자가 없는 회차는 합계 약 239.99로 ‘첫 출시 / 평가 점수 0.500 미만’이 표시됐다. [에디터 검증 31건](../GameDev/Verification-edit.txt)도 통과했다.
