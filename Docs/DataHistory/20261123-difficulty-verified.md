# 벙커 난이도 검증

기존 `data.bunker.rules`의 [BunkerRules.asset](../../Assets/Settings/Shelter/BunkerRules.asset)에 쉬움·중간 속도와 총 틱 분할 수를 저장했다. 주소는 `data/bunker-rules`다. 준비 시점과 적용 직전에 목록을 확인했으며 같은 역할의 정본이나 예약은 없었다. [필드 명세](../DataSpecs/BunkerRules.md) · [Addressables 빌드 결과](20261123-143545-0755983-data-built.md)

Unity Editor Play에서 타이틀 버튼과 파밍 완료 동작을 거쳐 실제 벙커 시뮬레이션을 960틱까지 진행했다. 일반 사건, 습격과 중간 발표 알림을 기록하고 각 틱이 예약과 일치하는지 비교했다. 팝업은 검사 코드가 닫았고 시간은 틱 단위로 진행했다.

| 선택 경로 | 초/틱 | 일반 사건 | 습격 | 중간 발표 |
|---|---:|---:|---:|---:|
| 일반 시작 · 어려움 | 0.33 | 20회 | 12회 | 3회 |
| 일반 시작 · 중간 | 0.5 | 16회 | 10회 | 3회 |
| 튜토리얼 완료 · 쉬움 | 1 | 12회 | 8회 | 3회 |

세 회차의 시계 마커 위치·개수와 첫 틱의 경계를 확인했다. 쉬움 회차는 엔딩 정산지의 다시 하기 버튼을 통해 파밍으로 돌아와 선택이 유지되는 것까지 확인했다. 1920×1080 게임 뷰에서 선택 화면과 세 버튼을 확인했다. Edit 검사에서 어려움 원본의 값이 보존됐고, 총 틱을 480으로 바꾼 임시 규칙에서는 쉬움·중간의 사건과 습격 간격이 절반으로 줄었다. Player 빌드와 수동 장시간 밸런스 검수는 수행하지 않았다.
