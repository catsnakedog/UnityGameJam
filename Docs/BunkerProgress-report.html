벙커의 시간을 만들고,
방 안의 작업을 연결했습니다.

공통 틱을 기준으로 게임 시한과 이벤트 주기를 관리하고, 방에 소속된 캐릭터의 개발 능력을 기존 분야별 진행도에 반영했습니다.

01 · 구현한 기능

①공통 틱과 게임 시한

총 N틱, 틱당 초, 각 이벤트 주기를 설정합니다. 누적 시간으로 틱을 처리하며 일시정지·재시작을 지원합니다. 마지막 틱의 작업을 반영한 뒤 개발을 종료합니다.

②랜덤 이벤트·좀비 침공

독립된 주기마다 알림을 발생시킵니다. 요청 범위에 맞춰 이벤트 내용, 확률 추첨, 좀비 생성·전투는 구현하지 않았습니다.

③방 타입과 캐릭터 소속

프로그래밍·그래픽·기획·공용·수면·좀비침공, 총 6종을 선택할 수 있습니다. 이동 목표와 실제 방 소속을 분리했습니다.

④개발 진행도 연결

프로그래밍·그래픽·기획 방에서 해당 능력을 합산해 기존 게이지를 올립니다. 여러 명의 기여를 합산하며 분야별 상한은 100%입니다.

02 · 방 소속에서 작업 반영까지

STEP 01이동 명령 수락

기존 방 소속을 해제합니다.

STEP 02실제 방 도착

도착한 방에 소속됩니다.

STEP 03작업 틱 도래

소속·활성 상태·방 타입을 확인합니다.

STEP 04분야별 진행도 증가

해당 능력 합 × 계수를 반영합니다.

이동 중, 사다리 이동, 복도, 닫힌 방, 비활성 캐릭터는 작업에서 제외됩니다. 다른 방을 통과하거나 목표로 지정한 것만으로는 작업하지 않습니다. 처음부터 방 바닥에 생성된 캐릭터는 해당 방에 소속됩니다.

03 · 작업 계산과 초기 방 배치

능력에 비례하는 작업량

소속 인원의 해당 능력 합
× 능력당 증가 계수

단위는 작업 1회당 퍼센트포인트(%p)입니다. 그래픽 방은 기존 캐릭터 데이터의 art 능력을 사용합니다.

능력 합 10 × 계수 0.1+1%p

세 분야를 모두 100% 채워도 총 틱까지 진행합니다.

05 · 검증 결과

Edit 검사 9개 통과

시간 누적, 일시정지, 틱 순서·상한, 종료 후 정지, 잘못된 입력 거부, SO 템포 변경과 원본 보존을 확인했습니다.

Play 검사 21개 통과

실제 데이터 로드, 캐시 공유, 이동·도착 소속, 3분야 능력 반영, 인원 합산, 비작업 상태 제외, 재시작·시한·마지막 틱 제출을 확인했습니다.

실제 실행 연결 확인

  • Unity 런타임 코드 컴파일 오류·경고 0.
  • Addressables 콘텐츠 빌드 성공. Use Existing Build 모드에서 실제 콘텐츠 로드.
  • 실시간 Update 실행 1.5초 후 현재 틱 1 확인.
  • 구독자가 없을 때 틱이 증가하지 않던 문제를 검증 중 발견해 수정한 뒤 재검증 완료.

07 · 플레이 방법과 남은 범위

바로 확인하는 순서

  1. Farming에서 사람을 벙커에 투입합니다.
  2. 벙커에 진입한 뒤 캐릭터를 선택하고 작업 방을 클릭합니다.
  3. 도착 후 작업 틱마다 해당 분야의 게이지 증가를 확인합니다.
  4. GameDevManager의 BunkerSimulation Inspector에서 현재 틱·남은 틱·Pause를 확인합니다.

벙커 씬을 직접 실행하면 기존 구조 명단 규칙에 따라 작업자가 없습니다.

후속 구현·미검증 항목

  • 랜덤 이벤트 내용, 좀비 생성·전투, 공용·수면 방 효과는 후속 범위입니다.
  • 점수 공식이 미정이므로 시간 종료 후 AwaitingScore 상태에서 외부 점수를 기다립니다.
  • Player 실행 파일, 영구 저장, 의도적인 로드 실패·복구는 검증하지 않았습니다.
  • 프레임 지연으로 여러 틱을 처리할 때는 처리 시점의 방 소속을 사용합니다.
