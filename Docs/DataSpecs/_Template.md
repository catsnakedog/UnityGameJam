# <데이터 이름> 명세

> 신규 생성 전에 이 양식을 복사하고 [DataRegistry](../DataRegistry.md)에 `planned`로 등록한다. `<...>`는 실제 조사 결과로 채우고 불명확한 부분은 `미정/미검증`으로 표시한다. 예시 값을 실제 밸런스로 확정하지 않는다.

## 식별과 담당 범위

| 항목 | 명세 |
|---|---|
| 안정적인 데이터 ID | `<domain.dataset>` — 행 ID/주소와 별도 |
| 상태 / 담당 기능 / 작업 ID | `<planned / 담당 기능 / 작업 담당자 또는 작업 ID>` |
| 스키마 버전 / 마지막 확인일 | `<버전 / 날짜>` |
| 목적과 소유하는 의미 | `<대상 + 속성 + 적용 범위>` |
| 검색 별칭 | `<한국어/영문 이름, 이전 이름>` |
| 제외 범위 | `<기존 데이터가 소유하는 속성, 런타임 상태 등>` |

## 필드 계약

필드가 많아도 모든 편집 필드와 관계를 적는다. `없음`, `미정`, `현재 미검증`을 구분한다. 선언하려는 제약과 이미 구현된 검증을 혼동하지 않는다.

| 필드 | 타입 | 의미/대상 | 단위 | 필수·빈 값·기본값 | 범위/상호 제약 | 참조 대상/고유 범위 | 검사 구현 또는 미구현 |
|---|---|---|---|---|---|---|---|
| `<필드>` | `<타입>` | `<의미>` | `<단위/무차원>` | `<누락 허용 여부 및 근거>` | `<제약>` | `<대상 데이터 ID.필드>` | `<검증기>` |

## 레코드·인스턴스·관계

- 키의 고유 범위, 대소문자/정규화, ID 발급 규칙: `<...>`.
- 현재 레코드/인스턴스와 상태: `<소수면 목록, 다수면 원본과 최신 전체 스냅샷 링크>`.
- 새 레코드마다 의미·상태·관계를 식별할 수 있도록 적는다. 동일 역할을 새 ID로 복제하지 않는다.
- 추가/정렬/삭제/비활성 정책: `<...>`.
- 외래키 대상 삭제와 저장 데이터 호환 정책: `<...>`.
- 현재 값/전체 스냅샷: `<정본 또는 DataHistory 링크>`; 문서의 숫자는 조회용 스냅샷이며 별도 편집 정본이 아니다.

## 기존 데이터와 중복 조사

| 비교 데이터/필드 | 검색어·확인한 파일/소비자 | 같은 의미인지 | 재사용·확장·분리 판단과 이유 | 관계/정본 |
|---|---|---|---|---|
| `<기존 데이터 ID 또는 미등록 발견 경로>` | `<조사 근거>` | `<단위·범위 포함>` | `<구체적 근거>` | `<참조/이전 방향>` |

“없음”으로 끝내지 말고 검색 범위와 결과를 적는다. `planned` 예약 및 적용 직전 최신 목록 확인 결과도 기록한다. 기존 데이터를 이전한다면 구 정본, 새 정본, 소비자 전환, GUID/ID 호환, 구 정본 폐기 조건을 적는다.
